# 散列表
前面介绍的顺序查找、折半查找，甚至二叉排序树中，查找的效率无不受到“比较次数”的制约。哪怕已经做到了对数级（如折半查找、平衡二叉树），也仍然不能突破这个“比较”的瓶颈。

有没有一种方法，不需要一轮轮地比较，而是一眼就能找到数据在哪里？这听起来像是开挂了，但现实中确实存在这样的结构 —— 散列表（Hash Table），根据音译， 通常也被称作哈希表。 



散列表的**核心思想**非常简单也非常聪明：

用一个“函数”直接计算出数据存储的位置，从而实现快速查找。就像查词典：你想查“apple”，不需要一页页翻，你根据字母表顺序直接翻到以“A” 开头的部分，这其实就是一种“散列”的思想。只不过在散列表中，是用一个“数学函数”来计算这个位置的。



# 散列表相关概念-散列函数
根据音译，通常也被称作哈希函数，是一种将关键字（Key）映射到散列表中某个地址（位置）的函数。它的作用是根据关键字，快速计算出该元素应该存储的位置。

可以把散列函数想象成一个“指路神器”或“数学变压器”，它接受一个输入（比如学号、名字、手机号），然后通过某种计算规则，把这个输入变成一个储物格编号（地址），告诉你数据该放在哪。

举例：

散列函数假设为 H(key) = key % 10

我要在下面数组中存入23和97，如何去存呢？

通过散列函数找到相应位置（下标为3的位置与下标为7的位置）存入

# 散列表相关概念-散列表
根据音译，通常也被称作哈希表，是一种根据关键字通过散列函数计算出位置，然后将数据存储在该位置的结构。散列表本质上是一个数组，但它不需要像数组那样依次查找，而是直接定位、直接查找。

可以把散列表看成一个“带编号的储物柜”，每个储物格都能放一个或多个数据，当要存放某个数据时，先通过“散列函数”决定放在哪一格，查找的时候也只需“按图索骥”，效率极高。要散列函数设计合理，查找效率可以接近 O(1)，比顺序查找、折半查找还快。



# 散列表的相关概念-冲突
当两个不同的关键字通过散列函数计算后，得到相同的结果值（地址），它们就会被映射到散列表的同一个位置，这种现象称为哈希冲突或散列冲突（简称“冲突”）

## 2、数字分析法
数字分析法是一种根据关键字中某些“数位”上的数字来构造散列函数的方法。其核心思想是：观察所有关键字在不同数位上数字的分布特征，选择分布较均匀的一位或几位，提取出来作为散列地址。例如，关键字是一串电话号码或学号，从中“挑几个有代表性的数字”来作为它在散列表中的位置



通常的操作步骤是：

（1）收集全部关键字样本

（2）统计每一位数字的分布情况

（3）选择分布最“离散”的几位数字

（4）将这些数字拼接/组合为散列地址

![](/images/yuque/541d15132ccc4534ca3c27e807d9a556.png)



## 3、平方取中法
平方取中法是指，先对关键字进行平方运算，然后从所得结果中间若干位中取出一部分数字，作为散列地址。散列函数的一般形式为：

H(key) = MiddleDigits(key × key) 

假设关键字是一串数字，先让它“自乘”一遍（平方），再从这个结果的中间部分挖出几位作为“门牌号”（即地址）。这个方法的核心理念是，平方运算会引入更多的组合信息，取中间部分可以“削弱”原始数字的某些集中性，提高地址分布的均匀性。

## 1、开放地址法
当一个关键字的散列地址已经被占用时，通过某种探测方式，寻找下一个空位，直到找到可以插入的位置为止。可以把整个散列表看作一个连续的“停车位”或“单元房”， 每个关键字要停放或入住时，会先查自己的“预定位置”（散列函数给出的地址）：

如果那一格空着，顺利入住；  
如果被占了，就换个位置继续试，直到找到空位为止。

### 线性探测法
线性探测法可以用该公式，Hi = (H(key) + i) % m (i = 1, 2, ..., m-1)，其中 H(key) 为散列表函数，m 为散列表长度，i 是一个增量序列，取值范围为 0～m-1。

### 二次探测法
二次探测法可以用该公式，Hi = (H(key)  ± i<sup>2</sup>) % m (i = 1, -1, 2, -2..., m/2, -(m/ 2))，其中 H(key)为散列表函数，m 为散列表长度，i 是一个增量序列。

### 伪随机探测法
伪随机探测法在每次冲突时，不是线性地、也不是按固定平方规律，而是借助一个伪随机序列来跳跃地探测下一个地址。

 Hi = (H(key) + i) % m ，i 是一个随机数



## 2、再散列法
当多个关键字经过同一个散列函数计算后出现冲突时，我们可以引入多个不同的散列函数，在发生冲突时依次使用备用的散列函数重新计算新的地址。这种处理冲突的方法称为再散列法



## 3、链地址法
将所有散列到同一个地址的关键字，用一个链表（或其它结构）连接起来，每个散列表元素指向一条链表

# 散列表查找流程
1. 计算散列地址

对待查关键字 key，使用事先设定好的散列函数 H(key)，计算其散列地址。

2. 访问该地址

如果该地址上存储的就是 key，那么查找成功；

如果该地址为空，说明 key 不存在，查找失败；

如果该地址上是另一个关键字，说明发生了冲突，必须进行“冲突处理”。

3. 冲突处理查找下一个地址

如果找到了目标关键字，则查找成功；

如果查到某个位置为空，或所有探测范围内都查不到，则查找失败。
